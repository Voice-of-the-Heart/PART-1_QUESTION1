# Bansara State SIA — Coverage Reconciliation and Missed-Settlement Cluster Analysis

Reproducible pipeline for GPS-track ingestion, QA, settlement attribution,
e-tally reconciliation, and missed-settlement cluster analysis for a
five-day house-to-house Supplementary Immunization Activity (SIA) across
four Local Government Areas in Bansara State (synthetic assessment data).

Full written analysis: `docs/WRITTEN_RESPONSE.pdf`. AI tool disclosure:
`AI_USE.md`. QA threshold justifications: `docs/QA_THRESHOLDS.md`.

This repository also contains a second, independent assessment deliverable
in `question6/` (a written capability-development response — no code or
data pipeline, see `question6/README.md`).

## Reproducing the results

```bash
git clone <this repo>
cd <this repo>
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Populate data/tracks/ with the raw <team_id>_<date>.csv files (see "Manual
# steps" below for why this one step isn't scripted), then:
bash run_pipeline.sh
```

All outputs land in `output/`: `campaign.sqlite` (full ingested/QA'd/flagged
track store), `settlement_final_reconciliation.csv` (settlement-level status
combining GPS and e-tally evidence), `ward_final_cluster_summary.csv`,
`A3_missed_settlement_clusters_FINAL.pdf`, `decision_brief_FINAL.pdf`, and
supporting intermediate CSVs from each stage.

Re-running `bash run_pipeline.sh` a second time is safe: ingestion is
idempotent (content-hash checked per source file; a genuine re-run inserts
zero new rows), and every downstream script recomputes cleanly from the
current state of `output/`.

## Manual steps (Requirement 2 disclosure)

**One step is not automated: placing raw track CSV exports into
`data/tracks/` before running the pipeline.** This is a data-provisioning
step, not a processing step — the files arrive as a data pack (or a live
export from the logger fleet's device-management system) outside this
repository's control, and different environments will source them
differently (a shared drive, an API pull from the DMS, a manual upload).
Automating that hand-off is an infrastructure integration decision for
whoever operates this pipeline in production, not something this repo can
responsibly assume. Everything downstream of that hand-off — ingestion, QA,
attribution, reconciliation, cluster analysis, map and brief generation — is
fully scripted and runs unattended via `run_pipeline.sh`.

`data/reference/` (masterlist, e-tally, inaccessible list, boundary
polygons) **is** committed, since these are small, static reference files
appropriate to version control directly.

## Key design decisions (see docs/Decision_Brief_Incident_Manager (1) for full justification)

- **Store:** SQLite (Python stdlib, zero install, fully portable for review).
  Schema and idempotency mechanism (deterministic content-hash key +
  `INSERT OR IGNORE`) are identical in PostGIS/DuckDB spatial; only the SQL
  dialect changes for a production deployment with network access to those
  engines.
- **No GDAL/pyproj/shapely/geopandas/duckdb available in this environment**
  (no network access for installation) — `src/utils/gpkg_wkb.py` is a
  ~60-line GeoPackage WKB parser and `src/utils/utm.py` a pure-numpy UTM
  Zone 32N forward projection (standard Snyder formula, WGS84 ellipsoid),
  used in place of the usual geospatial stack. Both are drop-in replaceable
  by `geopandas`/`pyproj` if that stack is available in your environment.
- **QA rule set:** every threshold is justified from first principles
  (device physics, campaign SOP, settlement spacing) in
  `docs/QA_THRESHOLDS.md`, not fitted to the data. One rule
  (`outside_campaign_window`) was added after inspecting the real data: 81%
  of raw points carry a timestamp date outside the actual 5-day campaign
  window, a systemic defect not anticipated by the original five-rule
  brief.
- **Reconciliation:** the final, defensible "missed" indicator requires
  agreement of both e-tally absence AND no QA-clean GPS fix in the
  settlement buffer, not e-tally alone. See
  `src/05_final_reconciliation.py`.
